feat(support): add Support screens, ticket dialogs and knowledge base

Builds the seven Support frames from the Figma file as three routes under
Shivalik Admin, reusing the existing primitives rather than adding
screen-specific layout.

Screens
- SupportTicketsPage serves both Client Issues (1180:36896) and Vendor
  Issues (1180:37141) via an `audience` prop off the route, the same
  construction as ClientsPage's `filter`.
- KnowledgeBasePage (1180:37386).
- Support sub-nav added to portals.js only: Sidebar already renders
  footerNav through SidebarNavItem, which handles `children` generically.

Dialogs (all on the shared Modal + TextField primitives)
- NewTicketDialog   1180:37549/37586/37608/37567 - Self/Client/Vendor
- TicketDetailDialog 1180:37631/37655
- EscalateDialog     1180:37643/37667
- ArticleFormDialog  1180:37689/37679 - add/edit modes

Shared-component changes
- Table: opt-in `density="dense"` (12px gutter) and `nowrap`. Nine columns
  at the default 24px gutter spend 432px on padding in a 1098px content
  area and wrap every cell. Both are opt-in because Finance's ten columns
  rely on wrapping to keep the row-action column on screen.
- SelectField: only supply `defaultValue=""` when uncontrolled. It
  previously set it unconditionally while every call site also passed
  `value`, so React warned about a controlled/uncontrolled select on every
  dialog in the app.
- StatCard: `tone` overrides the badge colour the arrow direction implies,
  for Support's "Avg resolution time" (a downward arrow is the good
  outcome).
- Modal: `showCloseButton`; new x-close icon and ProgressBar primitive.

Deviations from Figma are documented in src/README.md: the "Contect" typo,
the Add-knowledge-base frame's prefilled data, the split ticket-action
headers, and the Escalate frame's centred placeholder and stale ticket id.

Verified against the Figma frames in-browser at 1440px; lint and build
clean, console free of React warnings.
